# ФИЗМАТ — инструкция по публикации изображений: GitHub → Zomro

Версия: 26.11.2026. Постоянная памятка для добавления **теории, решений задач, схем и карточек** на платформу ФИЗМАТ.

**Репозиторий:** https://github.com/ireksmakov/physoge-site  
**Публикация:** https://github.com/ireksmakov/physoge-site/actions  
**Сайт:** https://fizmat-course.com/  
**Файл платформы:** `index.html`  
**Workflow:** `.github/workflows/deploy.yml`  

## 0. Главные правила

- Нельзя терять уже опубликованные задачи, уроки, изображения, карусели, симуляторы, анимации, кнопки, тесты и навигацию.
- Редактируем актуальную ветку `main`, **не заменяем** актуальный `index.html` старой локальной копией.
- **Не сжимать, не обрезать и не перекодировать** исходные PNG/JPG; формат 16:9 сохраняется. Для показа: `width:100%;height:auto;object-fit:contain` — это только адаптивный размер на экране, не изменение исходного файла.
- Пути в коде должны соответствовать реальным файлам. Не подставлять `images/` дважды, если используемая функция уже добавляет эту папку.
- Не хранить пароли, SSH-ключи и другие секреты в репозитории или переписке.

## 1. Подготовка фотографии

1. Создать и проверить учебную инфографику: тема, формулы, читаемость, пропорции.
2. Назвать файл латиницей без пробелов; пример: `62theory1.png`.
3. Проверить **полное** имя на Mac (`Получить информацию`) и затем в GitHub. Ошибка урока 62: файл оказался `potential-energy.png.png`, хотя ожидался `potential-energy.png`.
4. Если уже есть ошибка имени, не угадывать путь: проверить реальное название и исправить ссылку либо аккуратно переименовать сам файл.

## 2. Загрузка в GitHub

1. Открыть репозиторий: https://github.com/ireksmakov/physoge-site
2. Найти существующую папку выбранного урока (если её нет — создать); предпочтительная структура для теории:
   `images/course/ege-phy/m-8/l-9/theory/62theory1.png` (пример схемы имени, **не утверждение, что файл там уже существует**).
3. `Add file → Upload files`; выбрать PNG; проверить название и папку **до** подтверждения.
4. Сохранить коммит в `main` (или в отдельной ветке с PR, если правка сложная).
5. Открыть ссылку на только что загруженный файл в GitHub и убедиться, что он действительно существует и открывается.
6. Если нужного каталога ещё нет, GitHub покажет 404 — сначала создать путь.

## 3. Подключение во вкладку «Теория» или «Решение»

1. Взять **актуальный** `index.html` из GitHub и найти структуру нужного урока, его ID и механизм `renderTheory()` / `createImageCarousel()` либо соответствующее поле фото решения.
2. Для теории добавлять изображение **в механизм данных/рендеринга конкретного урока**, а не в произвольный глобальный обработчик. Для нескольких фото использовать существующую карусель. Не дублировать чужие фотографии и обработчики.
3. Проверить, ожидает ли функция относительный путь начиная с `images/` или уже добавляет этот префикс.
4. Пример обычного HTML, только если текущая архитектура урока действительно принимает HTML:
   `<img src="images/course/ege-phy/m-8/l-9/theory/62theory1.png" alt="Теория по теме урока" style="display:block;width:100%;height:auto;object-fit:contain">`
5. Убедиться, что фотография показывается **только в заданном уроке**, не перекрывает кнопки и сохраняет увеличение/просмотр. Не менять соседние уроки.
6. Не считать добавление одного отдельного JS-файла доказательством подключения: в уроке 62 такое решение не отображало фото, и понадобилась прямая вставка в рендер вкладки.

## 4. Публикация на Zomro

1. Действующий workflow: `.github/workflows/deploy.yml`, запускается при `push` в `main`.
2. На сервере используется каталог сайта `/var/www/physoge`. Workflow проверяет целевой сервер и каталог, использует SSH-секреты GitHub, создаёт резервную копию и отправляет файлы через `rsync`.
3. **Особенность текущего workflow:** он отправляет `index.html`, обязательные файлы и файлы из разницы `HEAD^..HEAD`. Если PNG загрузился в коммите с неудачной публикацией, следующий коммит **не обязательно** повторно отправит PNG. Поэтому перед успешным деплоем нужно убедиться, что нужный файл включён в список отправки.
4. В текущем workflow есть **специальные шаги только для урока 62**: проверка файла `images/ege-physics/lesson-62/theory/potential-energy.png.png`, передача его на Zomro в корень как `lesson-62-potential-energy.png` и вставка в теорию. **Не копировать эту логику на все уроки**; при следующей разработке лучше сделать общий безопасный механизм для медиа.
5. При ошибке workflow открыть соответствующий запуск и логи **первого красного шага**; исправить именно причину, не перезаписывать весь сайт.

## 5. Проверка после публикации

1. https://github.com/ireksmakov/physoge-site/actions → `Deploy to Zomro`.
2. Проверить, что **последний** запуск зелёный. Красный означает сбой; зелёный подтверждает выполнение workflow, **но не наличие фото в интерфейсе**.
3. Открыть https://fizmat-course.com/ и нужный урок/вкладку.
4. На Mac обновить `Cmd + Shift + R` (или открыть страницу без старого кэша).
5. Убедиться, что виден **сам PNG**, полностью и без обрезки; проверить мобильную ширину, увеличение, карусель/стрелки (если есть).
6. Проверить соседний урок, вкладку «Задачи», кнопки «Доска», «Анимация», «Решение», навигацию «Курсы», «Симуляторы», «Конструктор тестов». Отсутствие ошибок 404 и JS в консоли — дополнительная проверка.
7. Сообщать «опубликовано и видно на сайте» **только после проверки страницы**, а не только по зелёному статусу GitHub Actions.

## 6. Если фото не появилось

| Признак | Что проверять |
| --- | --- |
| GitHub 404 на папке | Папки ещё нет; создать каталог / README и загрузить PNG |
| GitHub 404 на картинке | Точное имя, включая расширение; регистр символов |
| Зелёный Actions, фото не видно | Пришёл ли PNG на сервер; совпадают ли URL и путь; вставлено ли в конкретную вкладку |
| Красный Actions | Открыть журнал первого упавшего шага; проверить наличие файла, SSH/rsync и шаблон |
| Картинка обрезана | Убрать `object-fit:cover`, фиксированную высоту и ограничивающий контейнер; поставить `height:auto;object-fit:contain` |
| Стрелки / масштабирование сломались | Проверить конфликты глобальных click-обработчиков и universal image viewer |

## 9. Единое оформление карточек задач (правило от 26.11.2026)

- **Все новые изображения условий в одном уроке должны иметь одинаковую типографику.** Для векторных карточек урока 59: Times New Roman, основной текст 32 единицы при полотне 1600×440, подписи схем крупнее. Для других форматов подбирать эквивалентный видимый размер, а не механически копировать координаты.
- **Не сжимать исходные фото**: не перекодировать, не ухудшать разрешение, не делать уменьшенную копию взамен оригинала, не обрезать условия и схемы. Масштабирование CSS `height:auto;object-fit:contain` допустимо только для адаптивного отображения; в полноэкранном viewer должен оставаться доступным оригинал.
- Избегать длинных горизонтальных полотен с мелким текстом: при одинаковой ширине блока они становятся нечитабельными. Переносить строки, оставлять схему отдельно, сохранять одинаковые поля, цвет и размер текста.
- При подключении к `getLessonTasks()` сохранять существующую кнопку «Решение», увеличение изображений и мобильный просмотр.
- Перед публикацией сравнить несколько карточек **на экране сайта** и проверить, что текст выглядит одинаковым по размеру.
